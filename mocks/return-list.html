A return is a restock's mirror image (#163): goods arriving at the warehouse to be counted, placed, and partly written off — but they left the building, went to a buyer, and came back, possibly broken. Ongoing is the in-flight state #144 asks about — created before the goods arrive; Received is where they are counted and inspected, so some units go back to a sellable shelf and some are written off (see RTN-0137). Team is the catalogue owner whose goods came back; Value is the expected refund value (final money follows from what condition actually arrived, so it settles on receipt, not creation). An order is optional (§5.2) — a walk-in parcel can be logged with none (RTN-0140). The date range filters on the created date; filters and search re-query the full set, so the page count reflects every return.

⚠ Open forks — the owner's to settle: whether "arrived, awaiting count" is a state distinct from Ongoing; whether judging is a step separate from receiving; what the money does (proposed: a second, negative revenue row); and which service owns a return. This mock takes one set of proposed answers so there is a shape to react to. Opening a return — receive & inspect — is the next screen.
