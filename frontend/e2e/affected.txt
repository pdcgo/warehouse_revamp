# The affected-spec finder's mapping — ONLY what reading the code cannot tell
# (docs/tools/san.md#test-affected). `go run ./tools/san test affected` traces most files by itself:
#   a Go file → the RPC handlers reaching it → the specs naming the RPC and the pages calling it;
#   a frontend file → the pages importing what it exports → their routes → the specs visiting them,
#   and its test ids → the specs using them.
# A line here ADDS specs for the files its glob matches; it never removes what the finder found.
#
# Format: <glob> -> <spec>, <spec>   # why
#   the glob is a repo-relative path; * stays inside a folder, ** crosses folders.
#
# Add a line when a full run catches a break that the affected specs of its slice did not run, and the
# finder could not have seen it.
