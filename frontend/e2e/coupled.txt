# Specs that must share ONE test database — `san test full --workers N` (docs/tools/san.md#test-full, backlog #51).
#
# Each worker of a parallel full run has its own database, and every batch inside it starts from a fresh clone. A
# spec that READS what an earlier spec wrote would find nothing there. Such specs are listed here, one group per line,
# and travel as one unit: one worker, one batch, one database, in name order. Nothing else is needed for the other
# kind of coupling — a spec that must sort AFTER another (it pollutes what the other counts: "named to sort after
# orders.spec.ts and statement.spec.ts"): inside a batch the specs still run in name order, and on another worker or
# in another batch they never meet at all.
#
# Format: <spec> <spec> …   # why
